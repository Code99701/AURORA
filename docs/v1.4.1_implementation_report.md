# AURORA v1.4.1 Implementation Report

**Milestone:** Canonical Ingestion Core + Robust PDF/OCR  
**Result:** Complete and locally verified  
**Date:** 26 August 2026

## Delivered

AURORA now processes native-text, scanned, image-only, vector-outline, and
mixed PDFs through one bounded canonical ingestion pipeline. Native text is
preferred page by page; OCR runs only where native extraction is insufficient.
The existing page/chunk/citation/preview architecture remains available while
new canonical runs, units, extraction metadata, and versioned provenance are
stored alongside it.

## Architecture changes

- An explicit allowlisted `AdapterRegistry` now resolves format adapters.
- The adapter protocol consumes a `BinaryIO` supplied by `FileStorage`; no
  adapter accesses a local object path.
- `CanonicalDocument` and `ContentUnit` create a provider-neutral normalized
  boundary.
- PDF locators are versioned JSON objects such as
  `{"v":1,"type":"pdf_page","page":7}`.
- Processing stages results and activates them atomically. Failed replacements
  preserve the last valid active pages, chunks, and index where possible.
- Indexing reads active canonical units first and falls back to legacy page rows.
- New chunks retain both old page provenance and canonical unit identity.
- RAG source references can expose canonical locator/extraction metadata without
  changing the JSON shape of legacy sources that lack it.
- Zero-source search/RAG/SSE requests return stable HTTP 409 code
  `NO_RESEARCH_READY_SOURCES` before embedding or generation calls.
- The frontend question textarea remains editable at zero sources and renders
  the backend's actionable message.

## Manual `intern.pdf` acceptance

The supplied private PDF was tested locally without copying it into the
repository or CI fixtures.

Observed result:

- valid, unencrypted, 13-page PDF;
- zero usable native characters on every page;
- every page classified for selective OCR;
- real Tesseract OCR succeeded on all 13 pages;
- page confidence ranged approximately from 0.875 to 0.936;
- document status became `PROCESSED` with stage `COMPLETE`;
- 13 active canonical OCR page units were stored;
- indexing stored 21 canonical-linked pgvector chunks;
- authorized retrieval returned eight items;
- RAG answer and server-controlled citations persisted;
- resolved citation reported page 7, method `OCR`, locator
  `{"v":1,"type":"pdf_page","page":7}`;
- the cited chunk's canonical locator independently matched page 7;

- frontend citation routing opens that document/page in the inspector.

For privacy, this run used deterministic local embedding and generation
providers. The configured Gemini key was not used because sending extracted
text from a private local PDF to an external provider requires the document
owner's explicit approval.

## Known limitations

- OCR processing is synchronous.
- OCR quality is document-dependent and is not intended for handwriting.
- Citations are page-level; stored OCR regions are not yet highlighted.
- Only PDF is registered in v1.4.1.
- Tesseract is a separate native runtime and must be installed/deployed outside
  Python package installation.
- Very large but allowed OCR jobs can occupy one API worker until the bounded
  timeout/page/resource limits terminate them.
