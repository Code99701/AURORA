5. EMBEDDED TECHNICAL & ARCHITECTURAL DOSSIER
5.1 System Architecture & Technical Stack
AURORA is architected as an enterprise-grade Modular Monolith designed for academic and corporate research assistance without external billing or cloud API dependencies:

Frontend: Next.js 16 (App Router), React 19, TypeScript, Vanilla CSS Modules. Uses a same-origin /api rewrite proxying to FastAPI. Features an interactive Research Desk with split-screen source evidence inspector, live Server-Sent Events (SSE) streaming tokens, and responsive document library.
Backend: Python 3.13, FastAPI, Pydantic v2, SQLAlchemy 2.0 ORM, Alembic database migrations.
Database: PostgreSQL 16 with the pgvector extension for storing 768-dimensional vector embeddings, full-text search (tsv vector generation), and relational schemas.
Embeddings: Local intfloat/multilingual-e5-base (SentenceTransformers, 768 dimensions), utilizing NVIDIA CUDA acceleration (RTX 4060 Laptop GPU, 8 GB VRAM) with automatic CPU fallback. Strictly adheres to E5 prefix conventions: "query: " for search queries, "passage: " for chunks.
Language Models (Dual-Engine with Quota Fallback):
Primary LLM: Google Gemini 2.5/3.6 Flash (gemini-3.6-flash) via Google AI Studio Free Tier.
Local Fallback LLM: Ollama running qwen3:8b (stored entirely on D:\AI\Models\Ollama to protect OS drive). Configured with think: false for low-latency generation.
Fallback Mechanism (backend/app/llm/fallback.py): AutoFallbackLLMProvider automatically catches Gemini HTTP 429 quota exhaustion (LLMQuotaExhaustedError), quota timeouts, and API connection failures, falling back transparently to local Ollama.
Multi-Format Ingestion Foundation: Canonical document model extracting 8 distinct format families:
PDF: Native extraction via pypdf with selective OCR fallback via Tesseract 5.3 (.runtime/tesseract/tesseract.exe).
DOCX: Paragraphs, headings, and nested tables via python-docx.
PPTX: Slide text, shapes, tables, and speaker notes via python-pptx (strict 1-based slide numbers).
XLSX: Multi-worksheet cell extraction via openpyxl.
TXT: UTF-8 text blocks.
Markdown: Sectional parsing by heading path.
CSV & TSV: Delimited row-group extraction.
Security & Multi-Tenancy:
Opaque HttpOnly session cookies.
Workspace authorization boundaries (OWNER / MEMBER roles). All document queries and vector searches strictly filter by workspace_id in SQL queries, completely eliminating cross-tenant leakage.
5.2 The 7-Stage Core Pipeline Workflow
Explain the end-to-end mathematical and operational dataflow: $$\text{Document} \xrightarrow{\text{1. Ingestion}} \text{Canonical Units} \xrightarrow{\text{2. Chunking}} \text{Structured Chunks} \xrightarrow{\text{3. Embedding}} \text{PostgreSQL pgvector}$$ $$\text{User Query} \xrightarrow{\text{4. Query Rewriter}} \text{Search Query} \xrightarrow{\text{5. Vector Retrieval}} \text{Context Assembly} \xrightarrow{\text{6. Grounded LLM}} \text{Answer + Citations}$$

Ingestion & Canonicalization: Files are validated (format allowlist, size limits), ingested through format-specific adapters, and stored as normalized ContentUnit rows with structured locator metadata (e.g., {"type": "pptx_slide", "slide": 2} or {"type": "pdf_page", "page": 4}).
Structure-Aware Chunking: Chunks are bounded to 800–1000 characters with 120-character overlap. Slide boundaries are respected; heading paths are preserved. Each chunk receives a contextual prefix: [Document: filename | Section: heading | Pages/Slides: start-end].
Local Vector Generation: Batches of passages prefixed with "passage: " are embedded via intfloat/multilingual-e5-base into 768-dimensional normalized vectors: $$\vec{v} = \frac{f_{\text{E5}}(\text{"passage: "} + T)}{|f_{\text{E5}}(\text{"passage: "} + T)|_2}$$
Context-Aware Query Rewriting (backend/app/rag/rewriter.py): In multi-turn chat sessions, follow-up queries (e.g., "Summarise the second one", "Explain it in Hindi", "What are its advantages?") are rewritten using recent conversation history into standalone, keyword-rich search queries while preserving the target language preference.
Semantic Retrieval with Positional Routing (backend/app/services/retrieval.py):
Cosine Similarity: Retrieved using 1 - cosine_distance over pgvector cosine operator <=>: $$\text{Similarity}(\vec{q}, \vec{d}) = 1.0 - \frac{\vec{q} \cdot \vec{d}}{|\vec{q}|_2 |\vec{d}|_2} = \vec{q} \cdot \vec{d} \quad (\text{since vectors are } L_2\text{-normalized})$$
Positional & Page-Range Routing: Regex detects page/slide constraints (e.g., "What is on slide 2?") and applies SQL filters DocumentChunk.page_number.between(start, end).
Keyword Boosting & Diversification: Matches on user terms boost candidate similarity by up to $+0.10$. A diversification algorithm ensures top-$k$ results represent multiple documents rather than clustering on one noisy section.
Grounded Generation & Refusal Discipline: The prompt instructs the LLM: "Answer ONLY based on the provided evidence. If the evidence does not contain sufficient facts, state honestly that the information is unavailable."
Durable Source Citation Provenance: Each cited passage is persisted in the rag_citations database table with its exact chunk_id, document_id, page_number, locator JSON, and cosine similarity. In the UI, citations render as interactive clickable badges (e.g., [1] · Slide 2) that open the verbatim source excerpt in a slide-out drawer.
